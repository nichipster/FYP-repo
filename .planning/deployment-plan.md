# Deployment Plan — NutriTrack Website

## 1. Architecture

```
Internet
   │
   ▼
[Reverse Proxy — nginx or Caddy]
   ├── / → Frontend container (port 3000)
   └── /api → Backend container (port 8000)
   
[Frontend: React Router SSR]   port 3000
[Backend: FastAPI + uvicorn]   port 8000
[Database: PostgreSQL 16]      port 5432 (internal only)
```

## 2. Docker Compose (Development + Production)

### `docker-compose.yml` (Development)

```yaml
version: "3.9"

services:
  frontend:
    build:
      context: ./fyp-project
      dockerfile: Dockerfile
    ports:
      - "3000:3000"
    environment:
      - API_BASE_URL=http://backend:8000
    depends_on:
      - backend
    restart: unless-stopped

  backend:
    build:
      context: ./backend
      dockerfile: Dockerfile
    ports:
      - "8000:8000"
    env_file:
      - ./backend/.env
    environment:
      - ENV=development
    depends_on:
      db:
        condition: service_healthy
    restart: unless-stopped

  db:
    image: postgres:16-alpine
    ports:
      - "5432:5432"      # exposed for dev tools (TablePlus, pgAdmin)
    environment:
      POSTGRES_DB: nutritrack_website
      POSTGRES_USER: nutritrack_web
      POSTGRES_PASSWORD: ${DB_PASSWORD:-dev_password_change_me}
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U nutritrack_web -d nutritrack_website"]
      interval: 5s
      timeout: 5s
      retries: 5
    restart: unless-stopped

volumes:
  pgdata:
```

### `docker-compose.prod.yml` (Production overrides)

```yaml
version: "3.9"

services:
  frontend:
    environment:
      - NODE_ENV=production
    restart: always

  backend:
    environment:
      - ENV=production
    restart: always

  db:
    ports: []    # don't expose DB port externally in production
    restart: always
```

Run production:
```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

## 3. Backend Dockerfile

```dockerfile
FROM python:3.11-slim

WORKDIR /app

# Install dependencies
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copy app
COPY . .

# Run migrations then start server
# (Alternatively: run migrations as a separate init container)
CMD ["sh", "-c", "alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2"]
```

## 4. Database Migration Strategy

### In Development
```bash
# After schema changes:
alembic revision --autogenerate -m "describe_change"
alembic upgrade head
```

### In Production (Docker)
The backend Dockerfile CMD runs `alembic upgrade head` before starting uvicorn.
This ensures migrations are always applied on container start.

**Risk:** If migration fails, container exits and doesn't start uvicorn.
**Mitigation:** Test migrations in staging before deploying to production.

### For Initial Setup
```bash
# One-time: create DB schema and seed content
docker compose exec backend alembic upgrade head
docker compose exec backend python scripts/seed_content.py
docker compose exec backend python scripts/seed_admin.py
```

## 5. Environment Variables

### Backend `.env` (production)
```
POSTGRESQL_DATABASE_URL=postgresql://nutritrack_web:STRONG_PASSWORD@db:5432/nutritrack_website
SECRET_KEY=<256-bit hex generated by: openssl rand -hex 32>
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=60
ALLOWED_ORIGINS=https://nutritrack.yoursite.com
ENV=production
```

### Frontend Environment
React Router SSR uses Node.js environment. The `API_BASE_URL` is used for server-side
fetch calls (inside loaders). Client-side fetches use relative `/api` paths which
are proxied by the reverse proxy.

## 6. Deployment Platforms

### Option A: Single VPS (Recommended for FYP)
1. DigitalOcean Droplet (1GB RAM, $6/month) or equivalent
2. Install Docker + Docker Compose
3. Clone repo, configure `.env` files
4. Run `docker compose up -d`
5. Configure nginx or Caddy for HTTPS (Let's Encrypt)

### Option B: Railway / Render / Fly.io
- Each service (frontend, backend, db) deployed separately
- Environment variables configured via dashboard
- No Docker Compose needed; use individual Dockerfiles
- Railway supports monorepo detection

### Option C: GitHub Pages + External Backend
Not recommended — SSR doesn't work with GitHub Pages.
The existing `static.yml` workflow is incompatible with React Router SSR.

## 7. Nginx Configuration (if using VPS)

```nginx
server {
    listen 80;
    server_name nutritrack.yoursite.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name nutritrack.yoursite.com;
    
    ssl_certificate /etc/letsencrypt/live/nutritrack.yoursite.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/nutritrack.yoursite.com/privkey.pem;
    
    # Public site + admin UI
    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
    
    # Backend API
    location /api {
        proxy_pass http://localhost:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 9. Deployment Checklist

Pre-deployment:
- [ ] `.env` configured with production values
- [ ] `SECRET_KEY` generated (not default dev value)
- [ ] `ALLOWED_ORIGINS` set to production domain
- [ ] `ENV=production` set (disables Swagger docs)
- [ ] `secure=True` on cookies (HTTPS in place)
- [ ] Database seeded with content

Post-deployment:
- [ ] `GET /health` returns 200
- [ ] `GET /api/content/faqs` returns FAQ data
- [ ] Admin login works at `/admin/login`
- [ ] Public pages show dynamic content
- [ ] HTTPS certificate valid
- [ ] APK download link works

## 10. Backup Strategy

Database backup:
```bash
# Daily cron backup
docker compose exec db pg_dump -U nutritrack_web nutritrack_website > backup_$(date +%Y%m%d).sql
```

For VPS: configure automated daily snapshots.
For Railway/Render: use built-in database backup feature.
